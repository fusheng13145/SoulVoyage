## 一、项目总览

### 1.1 一句话定位

面向大学生群体的**任务驱动型多智能体协同心理自助成长平台**：以情绪日记和人际模拟为两大入口，通过调度中心编排五个智能体，完成"觉察 → 溯源 → 训练 → 疏导 → 归档"的完整自助成长闭环。

### 1.2 目标用户与典型画像

| 用户角色 | 核心诉求 | 使用功能 |
|---|---|---|
| 大学生（主用户） | 情绪无处安放、人际冲突不会处理、压力大不知源头 | 日记、复盘报告、模拟训练、减压练习 |
| 高危边缘用户 | 已出现明显心理危机信号 | 被系统识别 → 转介提示（唯一"兜底"路径） |
| 管理员 | 系统运营、知识库维护、审计 | 后台管理、Neo4j 案例维护（脱敏） |

### 1.3 产品边界（必须背下来的红线）

**做：**
- 情绪觉察与可视化、压力来源梳理、认知误区提示
- 人际沟通**仿真训练**（练习性质，非治疗）
- 轻量化自助练习推荐（正念、54321、认知书写）
- 风险**筛查与归档**、高危时的转介提示

**不做：**
- ❌ 心理疾病诊断（不下"抑郁症"等任何结论）
- ❌ 替代心理咨询师/治疗行为
- ❌ 药物建议
- ❌ 未经用户授权的群体数据使用

**边界的技术落地（三处硬约束）：**
1. **Prompt 层**：所有 Agent 系统提示词统一注入 `DISCLAIMER_POLICY`（禁止诊断性表述、禁止医疗建议，遇到即改写输出）。
2. **输出校验层**：调度中心对 Agent 输出做规则过滤（匹配诊断词表：抑郁症/焦虑症/PTSD 等），命中则拦截并替换为中性表述 + 展示免责声明。
3. **前端层**：所有 AI 生成内容页面固定展示"本内容为自助参考，不构成医学诊断"水印条。

### 1.4 核心用例（Top 5）

| 用例 | 主流程 | 涉及 Agent |
|---|---|---|
| UC1 写情绪日记 | 撰写 → 情绪识别 → 压力溯源 → 生成复盘报告 → 推荐练习 | 1→2→4→5 |
| UC2 人际模拟训练 | 选场景 → 多轮扮演对话 → 结束复盘 → 沟通建议 | 3→2(可选)→5 |
| UC3 查看成长档案 | 拉取情绪曲线/报告列表/训练记录 → 导出 PDF | 5 |
| UC4 风险预警 | 持续评估 → 中/高风险 → 转介卡片 + 加密归档 | 5 |
| UC5 自助练习 | 按当前情绪状态匹配练习库 → 跟练打卡 | 4→5 |

## 二、系统总体架构

### 2.1 分层架构图

```
┌─────────────────────────────────────────────────────────────┐
│  接入层  Vue3 Web（对话面板 / 模拟器 / 图表 / 档案导出）        │
│          REST + SSE(流式输出)  ·  Nginx 静态资源与反代          │
├─────────────────────────────────────────────────────────────┤
│  应用层  SpringBoot Monolith（模块化分包，规模够前不拆微服务）    │
│  ┌────────────┐  ┌──────────────────────────────────────┐   │
│  │ Auth/用户   │  │        调度中心 Orchestrator          │   │
│  │ 模块        │  │ 任务引擎·状态机·Pipeline·消息总线·上下文 │   │
│  └────────────┘  └──────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Agent 层（业务推理单元，按需唤起，非常驻会话）             │   │
│  │  情绪感知 │ 溯源推理 │ 心智训练 │ 疏导干预 │ 风险归档      │   │
│  └──────────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────────┤
│  能力层  LLM 统一网关(封装多模型API/重试/计费) · KG 检索服务      │
│          Prompt 模板中心 · 输出校验器 · 加密服务                 │
├─────────────────────────────────────────────────────────────┤
│  数据层  MySQL(业务+档案) · Redis(上下文/任务态/限流)            │
│          Neo4j(心理学知识图谱) · 本地密文对象存储(导出文件)        │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键架构决策（ADR 摘要）

| 决策 | 选择 | 理由（面试表述） |
|---|---|---|
| 单体 vs 微服务 | 模块化单体 + 包内清晰边界 | 用户量可控，事务/部署简单；调度中心本身就是"逻辑微服务"，Agent 以接口隔离，将来可无痛拆出 |
| Agent 编排 | 自研任务调度引擎，不引入 LangChain 类框架 | 核心亮点自主可控：状态机 + Pipeline DAG + 结构化消息，能讲清每一步 |
| Agent 通信 | 不直接互调，全部经调度中心中转 | 解耦、可追踪、可重放；中间结果统一落库 |
| LLM 调用 | 统一网关接口 `LlmClient`，配置化切换模型 | 隔离供应商风险；集中做重试、超时、Token 统计、内容校验钩子 |
| 知识图谱 | Neo4j 存"结构化常识"，与 RAG 向量检索互补 | 约束输出、降低幻觉是差异化卖点 |
| 流式输出 | SSE | 训练对话需要打字机体验；比 WebSocket 简单够用 |

### 2.3 主数据流（UC1 日记全链路时序）

```
用户            Web             Orchestrator        Agents              Data
 │  提交日记 ──→ │  POST /tasks  │                    │                   │
 │             │──────────────→ │ 创建Task(PENDING)   │                   │
 │             │                │──状态→RUNNING──────→│                   │
 │             │                │ 派发 EMOTION_TASK ─→│ 情绪感知A         │
 │             │                │←── EmotionResult ───│────更新画像──→MySQL/Redis
 │             │                │ 派发 TRACE_TASK ───→│ 溯源推理A         │
 │             │                │                     │  (读Neo4j认知误区库)
 │             │   SSE:中间结果  │←── TraceResult ─────│                   │
 │             │←────────────── │ 派发 SUPPORT_TASK ─→│ 疏导干预A         │
 │             │                │←── SupportPlan ─────│                   │
 │             │                │ 派发 RISK_ARCHIVE ─→│ 风险归档A         │
 │             │                │                     │  风险分级/加密落库 │
 │             │  SSE:完成事件   │←── ArchiveReceipt ──│                   │

```

## 三、调度中心详细设计（核心）

> 这是整个项目的技术制高点，所有设计都要能被拆解成面试答题点。

### 3.1 领域模型

```
TaskDefinition（任务模板）──注册──▶ Orchestrator 任务工厂
TaskInstance（一次执行） 1──N TaskStep（对应一个Agent调用）
TaskStep 1──N AgentMessage（结构化中间结果，全量落库）
Session（用户会话）1──N TaskInstance
```

**核心类/接口（后端包结构 `com.soulvoyage.orchestrator`）：**

```java
public interface TaskDefinition {          // 每种业务流水线实现一个
    String code();                          // e.g. "DIARY_PIPELINE"
    List<StepSpec> pipeline(TaskContext ctx); // 支持按上下文动态裁剪步骤
}

public interface Agent {                    // 五大Agent统一抽象
    AgentCode code();
    AgentMessage run(AgentMessage input, AgentRuntime ctx); // 同步；流式另有 Flux 变体
}

public interface OrchestratorService {
    TaskView submit(String userId, TaskRequest req);
    void onStepCompleted(String taskId, String stepId, AgentMessage result);
    void onStepFailed(String taskId, String stepId, Throwable err);
}
```

### 3.2 任务状态机

```
PENDING ──▶ RUNNING ──▶ WAITING_USER ──▶ RUNNING      （模拟训练：等待用户多轮输入）
              │  ▲            │(超时30min)──▶ EXPIRED→ 交由归档Agent收尾
              ▼  └──重试(≤2,指数退避)──┘
          SUCCESS / PARTIAL_SUCCESS(某步降级) / FAILED / CANCELLED
```

状态流转全部写入 `task_step_log`（审计 + 可重放），Redis 缓存当前态用于查询加速。

### 3.3 Pipeline 编排（声明式）

内置流水线（M0–M4 落地四条，COMPANION 为 V2·M7 新增），新增业务只需注册 TaskDefinition：

| Pipeline | 步骤序列 | 动态分支 |
|---|---|---|
| DIARY_PIPELINE | 情绪感知 → 溯源推理 → 疏导干预 → 风险归档 | 风险=高 时插入"转介步骤"，跳过疏导推荐改为危机卡片 |
| SIMULATE_PIPELINE | 场景装载 → 心智训练(多轮循环) → 复盘 → 风险归档 | 循环退出条件：用户结束 / 轮数上限20 / 风险信号 |
| SUPPORT_PIPELINE | 情绪读取 → 疏导干预 → 风险归档 | 复用近24h情绪画像则跳过感知 |
| ARCHIVE_PIPELINE | 定时触发：画像更新 → 风险复评 → 档案生成 | 每日 03:00 |
| COMPANION_PIPELINE (V2) | 漫聊分段消化：摘要提取 → 情绪感知(source_type=CHAT) → [分支]轻量洞察 → 风险归档 | 异步触发（会话分段结束/日终）；**对话进行中的风险检测每轮同步实时跑，不经流水线** |

**步骤间数据流转规则：**
- 每步输出必须符合该步注册的输出 JSON Schema，校验失败 = 该步失败（触发重试/降级）；
- 中间结果**只增不改**（append-only），`agent_message` 表按 `task_id + step_seq` 排序即可完整还原一次执行——这就是"可追踪、可重放"。

### 3.4 Agent 间消息协议（AgentMessage）

```json
{
  "messageId": "am_01HT...",
  "taskId": "task_01HT...",
  "stepSeq": 2,
  "from": "TRACE_AGENT",
  "to": "SUPPORT_AGENT",
  "type": "MIDDLE_RESULT",          // REQUEST | MIDDLE_RESULT | FINAL | ERROR
  "payload": { "…结构化业务数据，见第四章各Agent契约…" },
  "contextRef": "ctx:session:123:turn:7",   // 大对象不进消息体，只放引用
  "trace": { "llmCalls": 2, "tokensIn": 850, "tokensOut": 320, "costMs": 4100, "model": "..." }
}
```

### 3.5 会话上下文管理

- **热上下文**（当前会话最近 N 轮、任务中间态）：Redis，Key 设计见 5.2，TTL 与会话过期一致；
- **温上下文**（近 7 天情绪画像摘要、用户偏好）：Redis 缓存 + MySQL 回源；
- **冷上下文**（历史会话/报告全文）：MySQL（敏感字段密文）。
- **上下文组装器 `ContextAssembler`**：每个 Agent 调用前，由调度中心按"该 Agent 声明的 contextNeed"（如 `emotionProfile:summary, lastReport, riskLevel`）组装最小上下文，**而不是把全部历史塞给模型**——省 token、控隐私、可解释。

### 3.6 并发、限流与降级

| 机制 | 设计 |
|---|---|
| 执行模型 | 虚拟线程（Java 21）或线程池 + 阻塞队列 `task_queue`(Redis Stream)；单用户同时最多 2 个活跃任务 |
| LLM 网关限流 | 令牌桶（用户级 6 req/min + 全局模型 QPS），Redis+Lua 实现 |
| 重试 | 步骤级最多 2 次，指数退避（2s/8s）；仅对超时/5xx重试，Schema校验失败不重试直接降级 |
| 降级 | LLM 全挂 → 日记功能返回"稍后再试"，但情绪打卡/练习库等纯规则功能仍可用；风险研判降级到**规则引擎版**（关键词+量表规则），宁可误报不可漏报 |
| 幂等 | 提交接口带 `clientReqId`；步骤回调带 `stepId+attempt` 去重 |

### 3.7 风险优先级抢占（安全设计亮点）

风险归档 Agent 是**每条流水线的强制末步**，调度中心不允许任何 Pipeline 绕过它（工厂层硬编码追加）。当风险结论为 HIGH 时：
1. 调度中心立即向该用户后续任务注入"危机模式"标记；
2. 危机模式下：其他 Agent 输出被替换为转介引导，前端弹出援助资源卡片；
3. 全过程写入 `risk_event` 与审计日志（加密）。

> **V2 修正（M5，设计缺陷复盘）**：M0–M4 实现中危机标记是只进不出的布尔位，用户一旦触发 HIGH，DIARY_PIPELINE 将永久退化为两步、再也拿不到复盘报告。V2 把危机升级为**生命周期状态机** `NORMAL→CRISIS(7天强干预)→COOLING(链路恢复+常驻关怀横幅)→NORMAL(画像双周达标自动降级 或 管理员复核结案)`，累计再入者进强制人工复核队列；`RiskRules` 同步补否定/引文前窗检测并词表外置热加载。详见下篇S1。

## 四、五大智能体详细设计

> 每个 Agent 四要素：**输入契约 / 输出契约 / Prompt 与知识依赖 / 异常兜底**。输出契约 = JSON Schema，落库前由调度中心统一校验。
> V2 新增第六个 Agent（4.6 漫聊陪伴），走同一 AgentRegistry 注册机制——正是"新增 Agent 无需改动整体架构"这一设计主张的落地验证。

### 4.1 情绪感知 Agent（EmotionAgent）

**职责**：文本 → 情感识别 + 强度 + 事件标签 → 更新情感画像 → 输出情绪时序点。

**输入契约**
```json
{ "diaryText": "string, ≤5000字", "diaryDate": "2026-09-19",
  "profileSnapshot": { "recent30d": [ { "date":"...", "primary":"...", "intensity":0 } ] } }
```

**输出契约（EmotionResult）**
```json
{
  "primaryEmotion": "愤怒",                    // 枚举：喜悦/悲伤/愤怒/恐惧/焦虑/羞耻/平静/麻木… (16基础情绪表)
  "secondaryEmotions": [ { "emotion":"委屈", "weight":0.6 } ],
  "intensity": 0.75,                            // 0~1
  "valence": -0.6,                              // 效价 -1~1，用于曲线双指标
  "eventTags": [ { "tag":"人际冲突", "scene":"宿舍", "evidence":"原文引用句" } ],
  "trajectoryPointId": "et_...",
  "profileDelta": { "stressorFreqUpdate": { "学业压力": 1 } }
}
```

**Prompt 策略**：Few-shot（8个标注样例）+ CoT（先列证据句再定性）+ 强制 JSON（function calling / response_format）。事件标签为**闭集枚举**（防止标签爆炸，画像可统计）。
**知识依赖**：Neo4j `EmotionCategory` 节点（情绪枚举与近义词归一）。
**兜底**：文本为空/纯表情 → 输出"平静/低强度 + needsClarify"，不猜测。

### 4.2 溯源推理 Agent（TraceAgent）

**职责**：基于 EmotionResult 推理压力源、识别认知误区、生成"事件-情绪-想法"复盘报告；可选以苏格拉底提问发起 1~3 轮引导对话。

**输入契约**：EmotionResult + 近14天情绪时序 + 用户画像摘要 + KG 检索结果（由检索服务预先注入，Agent 不裸查库）。

**输出契约（TraceResult）**
```json
{
  "stressors": [ { "source":"学业压力", "confidence":0.8, "evidence":["…"], "timeRange":"近两周" } ],
  "cognitiveDistortions": [
    { "name":"灾难化思维", "kgNodeId":"cd_disastrous", "trigger":"挂了就要毕不了业",
      "challengeQuestion":"如果朋友挂了这一科，你会认为他一定毕不了业吗？" }
  ],
  "socraticQuestions": ["string，2~3个，用于引导反思"],
  "report": { "eventSummary":"…", "emotionSummary":"…", "thoughtSummary":"…",
              "insight":"…", "suggestion":"…" },
  "riskSignals": [ { "type":"持续低落两周+", "level":"MEDIUM" } ]   // 供风险Agent消费
}
```

**Prompt 策略**：以认知行为疗法（CBT）"情境-想法-情绪"框架作为输出骨架模板；每条认知误区**必须引用原文证据**（约束幻觉）；`challengeQuestion` 用提问句式而非断言句式（自助而非说教）。
**知识依赖（核心卖点）**：Neo4j 认知误区库——`CognitiveDistortion-[:EXHIBITS]-[:TRIGGERS_IN]-[:CHALLENGED_BY(SocraticPattern)]`，检索到的节点 ID 回填到输出，保证每条误区有出处可溯源。
**兜底**：证据不足时输出 `insufficientEvidence:true`，报告降级为"仅情绪记录摘要"，**不强行归因**。

### 4.3 心智训练 Agent（SimulateAgent）

**职责**：人际场景仿真核心。一场训练 = 1 个用户角色 + 1~2 个 NPC 角色，多轮博弈对话，结束后自动生成复盘。

**场景卡（SceneCard，存 MySQL + 配置化，4 个核心场景预置）：**

| 场景 | 冲突核心 | NPC 人设要点 | 难度分级 |
|---|---|---|---|
| 宿舍冲突 | 作息/卫生边界 | 固执但讲理的室友，会防御性反驳 | 温和/普通/强硬 |
| 小组项目分歧 | 分工与搭便车 | 划水但会甩锅的同学 | 温和/普通/强硬 |
| 亲子沟通 | 期望压制与表达 | 关爱但不擅倾听的母亲 | 温和/普通 |
| 亲密关系矛盾 | 需求错位 | 回避型依恋的伴侣 | 普通/强硬 |

**场景卡结构**：`sceneCode, background(给用户), npcPersona(人设/动机/底线/情绪触发点), goalDimensions(本轮考察:倾听/边界表达/共情/让步策略), maxTurns:20, endingConditions`。

**运行机制（同一 Agent 内多角色，不是多个 Agent）：**
- 每轮：用户输入 → `NpcDirector`（导演模块，维护 NPC 情绪状态机：中立→不满→激化/缓和）决定 NPC 反应强度 → LLM 以 NPC 人设生成回复；
- NPC 不"读心"：只知道用户说出口的话，保证博弈真实感；
- 情绪状态、轮次、关键事件由导演模块记为 `transcript + stateLog`。

**输出契约（SimulateReview）**
```json
{
  "turnScores": [ { "turn":5, "dimension":"边界表达", "grade":"B", "comment":"…" } ],
  "keyMoments": [ { "turn":8, "type":"升级冲突", "quote":"…" } ],
  "overall": { "avgScore":72, "strengths":["共情开场好"], "weaknesses":["第8轮人身评价"] },
  "rewriteSuggestions": [ { "turn":8, "original":"…", "optimized":"把'你总是…'换成'我注意到这周有三次…，我希望…'" } ]
}
```

**Prompt 策略**：NPC System Prompt = 人设卡 + 当前情绪档位 + "禁止替用户说话/禁止上帝视角"约束；复盘 Prompt 引入非暴力沟通（NVO）四要素评分标准（观察/感受/需要/请求）。
**兜底**：用户在对话中流露真实危机信号（区别于剧情）→ 导演模块检测 → 立即跳出剧情，触发风险流程并温和结束。

### 4.4 疏导干预 Agent（SupportAgent）

**职责**：按当前情绪 + 压力类型匹配轻量自助练习，生成短期减压方案与心理科普。

**练习库（规则层，MySQL 表 `exercise_library`，不依赖 LLM 生成动作——安全兜底）：**

| 练习 | 适用 | 形态 |
|---|---|---|
| 54321 感官着陆 | 焦虑/急性紧张 | 引导式步骤打卡 |
| 正念呼吸(4-7-8) | 高压/失眠前 | 计时器+语音文案 |
| 认知书写(三栏表) | 溯源Agent发现认知误区时 | 情境/想法/替代想法填写 |
| 行为激活清单 | 持续低落 | 微任务勾选 |
| 情绪命名练习 | 情绪麻木/混沌 | 词库选择+造句 |

**输入契约**：EmotionResult(或快照) + TraceResult.stressors + 用户历史练习完成偏好。
**输出契约（SupportPlan）**
```json
{
  "planTitle": "考前焦虑 3 日舒缓方案",
  "matchedExercises": [ { "exerciseId":"ex_54321", "reason":"焦虑效价高且为急性场景", "schedule":"今晚睡前" } ],
  "psyEducation": { "topic":"焦虑的躯体信号", "content":"≤300字科普", "kgSource":"node:psy_anxiety_body" },
  "disclaimer": true                       // Schema 强制字段，恒为 true
}
```

**Prompt 策略**：方案 = 练习库 ID 检索 + LLM 只负责"组合、排序、写引导文案"，**不允许发明新疗法**（闭集选择式生成，KG 约束思路的延伸）。
**兜底**：无匹配 → 推送通用 grounding 练习；HIGH 风险画像下本 Agent 被调度中心旁路。

### 4.5 风险研判 & 归档 Agent（RiskArchiveAgent）

**职责**：全链路唯一出口。风险分级 → 高危转介 → 数据加密归档 → 成长档案与导出。

**风险分级规则引擎（LLM 语义信号 + 规则双轨，取较高级别，规则拥有一票升级权）：**

| 级别 | 触发示例 | 系统动作 |
|---|---|---|
| LOW | 一般负面情绪 | 正常归档 |
| MEDIUM | 持续低落≥2周信号 / 自我否定密集 / TraceResult 含中危 riskSignals | 归档+升级转介资源展示位+推荐咨询中心科普 |
| HIGH | 自伤/自杀意念表述(关键词规则 or LLM判定) / 训练剧情外真实危机 | 立即转介卡片(校心理中心/全国24h心理援助热线 12356 等) + 危机事件加密归档 + 标记用户进入危机模式 |

> 设计原则：**宁可误报，不可漏报**；HIGH 判定不需要 LLM 单独拍板，规则命中即 HIGH。

**输出契约（ArchiveReceipt）**
```json
{ "riskLevel":"MEDIUM", "riskEventId":null,
  "archived": { "emotionPoints":2, "reports":1, "messages":5 },
  "encryption": { "algo":"AES-256-GCM", "keyVersion":"k3" },
  "profileUpdated": true }
```

**成长档案**：日报 → 周报（情绪曲线 + 压力源 Top3 + 误区改善趋势 + 训练分数趋势）→ 可导出 PDF（iText/OpenPDF 渲染，导出文件本身加密存储、链接限时）。
**兜底**：归档失败 → 任务不判 SUCCESS，进入 FAILED 重试队列并告警（档案完整性 > 用户体验）。

### 4.6 漫聊陪伴 Agent（CompanionAgent，V2·M7 新增，详见下篇C0）

**职责**：自由倾诉/日常陪伴对话（"树洞漫聊"），低门槛数据入口；对话记录经用户知情后沉淀为画像与风险数据源。

- **实时会话引擎**：复用模拟训练的 SSE 流式与断线处理，但去掉 NpcDirector 张力状态机，替换为**情绪响应策略**（跟随用户效价：负面时降能量匹配、稳定后温和拉升，禁止强行正能量）；ContextAssembler 注入近 7 天画像摘要 + 事件标签（不注入原文）实现"记得你"的追问回引。
- **逐轮实时风险检测（P0 中 P0）**：每轮用户输入在回合入口同步跑 `RiskRules.scan`，命中 HIGH → 当轮回复替换为温和陪伴 + 转介卡流内插入 + 进入 S1 危机生命周期；倾诉场景是高危表述最高发入口，不允许延迟到会话结束批量判。
- **异步消化**：会话分段（自然日+30min 静默）结束后走 COMPANION_PIPELINE（摘要提取 → 情绪感知 source_type=CHAT → 风险归档），TRACE 仅在显著负面时按分支产出可忽略的"轻量洞察"卡。
- **边界与自主权**：输出过 DISCLAIMER_POLICY + 诊断词拦截；首次进入明示"自助陪伴工具，非心理咨询师"；用户可对单条消息标"这句别分析"、可在设置整体关闭漫聊参与分析；连续 3 日超 100 轮/日触发一次"写日记深梳理/看校心理中心"的防依赖引导。
- **数据**：`companion_session/companion_turn`（用户消息 ✦ 加密），纳入注销密钥销毁与档案导出；软上限 200 轮/日 + 用户级限流控 LLM 成本。

## 七、安全与隐私设计

### 7.1 加密体系（面试可讲的完整方案）

**信封加密**：
- 主密钥 MK：存服务器本地 keystore/环境变量（进阶：接 KMS），启动时解密进内存；
- 数据密钥 DK：`data_key` 表登记版本，用 MK 加密存储；
- 敏感字段（日记原文、报告正文、对话记录、手机号）：按字段 AES-256-GCM 加密，密文+IV+tag 一起落库；
- **密钥轮换**：新写入用新版 DK，旧版保留解密，后台任务分批重加密；
- **注销即遗忘**：销毁该用户专属 DEK（用户级派生密钥：HKDF(MK, userId+salt)），数据物理上不可恢复。

### 7.2 权限与访问控制（SpringSecurity）

- RBAC：USER / ADMIN 两角色起步；`@PreAuthorize` + 资源属主校验（所有 `user_id` 维度接口强制断言"资源属于当前登录用户"，防越权 IDOR）；
- 审计：登录、导出、删除、管理端全部写 `audit_log`，`hash_chain = SHA256(prev_hash + record)` 防篡改；
- 接口防线：全局+用户级限流、验证码注册、JWT 黑名单登出、Cookie SameSite、CSP、导出文件限时一次性链接。

### 7.3 危机响应 SOP（产品合规核心）

```
HIGH 判定 → ① 当前页强制转介卡片（校心理中心预约方式 + 12356 热线 + 400-161-9995）
          → ② 会话内温和话术（不评判、不诊断、鼓励求助）
          → ③ 用户点击"我需要帮助"→ 记录 action_taken（仅记录行为，不通知任何人——学生场景无监护人链路）
          → ④ risk_event 加密归档 + 保留人工复盘入口（管理员只见编号，解密需二次授权）
```

**边界声明**：平台无强制干预义务与能力，转介即服务终点——这句话要写进用户协议并在界面明示。

### 7.4 AI 内容安全

- 输入侧：prompt 注入防护（把用户输入永远置于 user message，模板不拼接用户可控指令）；
- 输出侧：诊断词表拦截 + 免责声明强制注入 + KG 节点存在性校验（见 4.5 与 5.3）；
- LLM 供应商侧：日志脱敏（外发 API 不留存原文的策略写入供应商协议，自建调用日志仅存 metadata 不存 payload 明文）。

> 完整 token 表、组件规格与逐页交互稿见下篇·五、下篇·六两章；本节为系统设计层面的规范性摘要。
> **视觉基线已定稿**：交互效果以 [V2 交互原型](demo/V2交互原型.html) 实测为准，M6 实现逐屏对照验收。

### 8.1 技术选型

Vue3 + TypeScript + Vite · **Pinia 实装**（auth/content/crisis/plan 四个 store，收编散落的 localStorage 与重复请求）· Vue Router（路由命名 + 转场）· ECharts（按需注册）· `@vueuse/core`（滚动/媒体查询/减动效检测）· axios + fetch-SSE（含重连）。
**不引入第三方 UI 库**：自建 `Sv*` 组件库（约 18 个组件），换取完全定制力与零覆盖负担。

### 8.2 设计哲学（HIG 三原则落地）

- **清晰**：文字优先、系统字体栈（SF Pro / PingFang SC）、留白代分割线、自绘 SVG 图标全面替换 Emoji；
- **顺从**：界面服务于情绪数据，chrome 材质化（导航/TabBar/弹层 `backdrop-filter: saturate(180%) blur(20px)`）；
- **深度**：分层阴影 + 转场保留空间连续性（push/pop、sheet 底层视差缩小）。

### 8.3 设计 Token（CSS 自定义属性，light/dark 双值）

- 色彩：品牌屿蓝系（`--sv-indigo #5B6CFF`）+ iOS 系统语义色（`--sv-blue/red/amber/mint`）+ **16 情绪专属色谱**（打卡盘/日历/曲线共用同一色源）；dark 模式跟随系统可手动切换；危机相关面在 dark 下提高对比、禁用纯红大铺底。
- 排印：LargeTitle 34 → Caption2 11 九级字阶，正文 17/1.6，数值 tabular-nums，阅读列 68ch。
- 形态：4pt 间距体系；卡片圆角 20px、sheet 顶 28px、控件 14px、胶囊 999px；阴影两级（dark 下以描边替代）。
- 触感：`SvHaptic` 指令统一按压 `scale(0.97)` 反馈（危机场景不加戏）；全局尊重 `prefers-reduced-motion`。

### 8.4 信息架构与页面地图（5 Tab + 危机全局可达）

```
今日(Tab1)  日记(Tab2)  练习(Tab3)  洞察(Tab4)  我的(Tab5)   /crisis(公开路由,任意页2击可达)
今日   = 时段问候 + "来漫聊/写日记"双入口大卡 + 心情打卡盘(SvEmotionDial) + 情绪日历热力条 + 今日计划卡 + 最近动态 + 入口列表
树洞漫聊 = /companion 全屏连续对话（V2·M7，C0）：逐轮危机防护、画像回引、"这句别分析"、续聊胶囊
日记   = 时间线列表(月分组/左滑删除，含漫聊消化摘要角标) + 沉浸编辑器(自动草稿) + 分析全屏页(SvTimeline 流式展开)
练习   = 进行中计划横滑 + 场景卡库(10 场景/难度/继续未完成徽标) + 按情绪筛选的沉浸跟练(呼吸环/54321分步)
洞察   = 效价渐变曲线 + 压力源环形图 + 误区趋势 + 训练四维雷达 + 周报入口
我的   = inset-grouped：档案(来信/成就墙/导出) · 提醒偏好 · 隐私中心(数据导出/注销) · 常驻"需要帮助?"
管理端 = 桌面侧边栏工作台(任务监控/风险复核/内容/用户/审计)，同一 token 的紧凑密度变体
```

**移动端优先**：≥1024px 视口收敛为居中 430px 移动画布 + 品牌氛围背景，不做独立桌面布局；PWA 可安装（manifest / theme-color / `viewport-fit=cover` / safe-area 全量处理）。

### 8.5 关键组件与体验规范

- **SvTimeline（AgentFlowProgress 重制）**：竖版材质节点时间线，running 节点呼吸光晕 + 中间结果滚动摘要，节点可点开查看结构化输出；断线显示"正在重连（第 N 次）"——**把调度协同与 S4 可靠性一并显性化给用户/面试官看**；
- **SvBubble 聊天**：iMessage 质感渐变气泡、"对方输入中"三点指示、自动滚底、键盘 visualViewport 避让；
- **SvSheet / SvDialog / SvToast / SvSkeleton**：全局消灭白屏、无回执错误与"卡在加载中"三类旧病；导出等不可逆动作必须 Dialog 确认（一次性链接误点即作废）；
- **免责与危机**：AI 内容页免责条升级为可展开"为什么这么说"（露出 KG 出处）；`risk:crisis` 生效时全局顶部常驻求助横幅；危机热线全部 `tel:` 一键拨号且带静态兜底数据；
- **动效**：路由 push/pop 320ms spring、tab 淡入、sheet 视差，统一 `cubic-bezier(0.32,0.72,0,1)`；
- **无障碍（上线门禁）**：全交互件 label/role/aria、状态不只靠颜色、对比度过 WCAG AA、触摸目标 ≥44px、Lighthouse a11y ≥90；
- **文案系统**：人设"温柔、克制、不评判的岛屿向导"；禁词：治疗/患者/症状/必须；空态必须含引导句，错误回执必须含下一步动作。

## 十一、附录

### 11.1 三分钟项目自述（面试版脚本骨架）

1. **是什么**：面向大学生的任务驱动多 Agent 心理自助平台，五个 Agent 覆盖"觉察-溯源-训练-疏导-归档"闭环。
2. **难点在哪**：不是调五次大模型——是自研调度引擎（状态机 + Pipeline DAG + Schema 校验的结构化消息，中间结果 append-only，可追踪可重放）；是知识图谱反向校验 Agent 输出压幻觉；是"宁可误报"的风险双轨判定和信封加密 + 密钥销毁式注销。
3. **边界意识**：主动不做诊断，三层硬约束落地（Prompt/校验器/前端），高危转介——体现产品与合规思维。
4. **数据说话**：任务成功率 100%（`task_instance` 233/233 全部终态 SUCCESS，含失败任务手动重跑后续跑到终态）；1k DAU 折算压测（80 虚拟用户 × 36s 思考，实测 2.49 req/s ≈ 目标流量 1.13x，317s / 790 请求 / **0% 错误率**）下读接口 p95 ≤17ms（日记 5.6 / 任务 5.9 / 每日一读 16.3）、写接口 p95 ≤34ms、漫聊单回合 p95 531ms（含网关延迟注入），整体 p50 6.2ms；token 成本直读 `task_step_log`——7 日窗口 196 个 LLM 步骤、in 113,346 / out 20,904，管理端按 Agent×模型聚合且跨重启可回放（当前数值由 Mock 回放器的 usage 字段供给，链路已通、真实账单待 llm-gateway 接入）；高危句式 100% 召回是 CI 单独成步的硬卡点，日记/漫聊/训练三条输入路径的危机一票拦截各有集成测试兜底。

| 追问 | 应答锚点 |

| 断裂点 | 现状 | 后果 |
|---|---|---|
| 危机模式有去无回 | `crisis_flag` 只能置 1，无任何恢复路径 | 用户误触一次危机词 → 日记流水线永久退化为两步，**再也拿不到复盘报告**，产品对本人关闭 |
| 日记原文不落库 | `diary` 表建了但零写入 | 无法回看、编辑、删除自己的日记——"日记产品"没有日记本 |
| 注销即遗忘有函数无端点 | `destroyUserKeys()` 零调用 | 合规红线（个人信息法"删除权"）未闭环 |
| 无管理端 | `/admin/**` 预留但 404 | 风险复核、内容维护、故障处理全部无人可做，不具备运营资格 |

### 1.2 功能宽度不足

- 内容量：4 场景 / 5 练习 / 12 误区节点，一次用完即流失；
- 无打卡体系：练习只有单点记录（可无限重复打卡、无日期维度）、无连续天数、无提醒；
- 无"每日"理由：产品只有"有事才来"的工具属性，缺少日常陪伴形态（快速打卡、每日一读、周报推送）；
- 报告/训练/任务都没有列表与检索，历史产出几乎不可再消费。

### 1.3 体验粗糙

前端仅 1573 行、全局样式 3 行、零组件库、零动效、零暗色、零移动端适配、Emoji 当图标、无障碍命中为 0；SSE 无重连无重放，早期事件竞态丢失会让进度条卡死；聊天不自动滚底、导出后回不到常规视图。

### 1.4 生产不可部署

无分页约定一致性、时区全用 UTC（东八区跨日错 8 小时）、SSE 与导出快照都是单节点内存、无 token 成本落库、无 CI、refresh token 不轮换。

> **结论：架构地基是好的，V2 要做的不是重写，而是"补闭环、加宽度、上质感、能运营"。**

## 下篇二、设计原则与不变项

### 2.1 永不偏移的基础（红线）

1. **调度中心中枢地位不变**：所有 AI 链路仍经 Orchestrator 编排，Agent 不互调；新增 AI 能力 = 新注册 TaskDefinition，不改编排引擎核心。
2. **五大 Agent 职责边界不变**：情绪感知 / 溯源推理 / 心智训练 / 疏导干预 / 风险归档，各自输入输出契约（JSON Schema）只做兼容性扩展。
3. **产品边界三层硬约束不变**：不诊断、不说教、不药物建议；Prompt 层 + 输出校验层 + 前端免责层。
4. **风险双轨研判只增强不削弱**：规则一票升级权保留，"宁可误报不可漏报"保留；任何新功能（打卡、提醒、看板）不得成为绕过风险归档的通道。
5. **敏感数据信封加密 + 注销即遗忘**是产品卖点而非负担，全部新表沿用 `✦` 加密规范。

### 2.2 V2 新增设计原则

- **温柔的产品观**：不做打断式增长（无推送轰炸、无排行榜、无 PVP  gamification）；游戏化只用于"记录自己的连续性"（streak 断了不惩罚、可补签）。
- **危机可达性最高优先**：`/crisis` 永远公开可达、永远一键拨号、任何页面 2 次点击内可到达。
- **iOS 原生质感**：不是"仿 iOS 皮肤"，而是采纳 HIG 的三大理念——**清晰（clarity）、顺从（deference to content）、深度（depth）**，配合系统级组件语言与动效物理感。
- **离线优先的本地状态**：草稿、打卡意图先落本地再同步，心理记录工具不能因为网络失败丢用户的话。

## 下篇四、功能扩展详细设计

### L1 安全与信任闭环（P0）

#### S1 危机模式生命周期（本版最高优先）

**动机**：修复"一次误触、永久降级"的致命缺陷，同时把危机响应做成可运营的完整 SOP。

**设计**：`crisis_flag` 从布尔位升级为状态机：

```
NORMAL ──HIGH判定──▶ CRISIS(强转介，日记链路退化为两步)
   ▲                    │ 冷却期 7 天届满
   │                    ▼
   │              COOLING(链路恢复完整流水线，但：
   │                     ① 结果页顶部常驻求助横幅（可折叠不可去除）
   │                     ② 每次任务照常跑风险归档
   │                     ③ 连续 2 个自然周画像 avgValence > -0.3 且无新 risk_event
   │                        → 系统自动降级 PROBATION→NORMAL（crisis_end 留痕）
   │                    │ 期间再次 HIGH
   │                    ▼
   └──管理员复核结案──── RE-ENTRY(重新计时 7 天；累计 2 次进 REVIEW 队列强制人工复盘)
```

**触点**：
- `user` 表加 `crisis_state / crisis_started_at / crisis_ends_at`；`DiaryPipeline.steps()` 改判 `crisis_state == CRISIS`（仅强干预窗口内跳过 TRACE/SUPPORT），COOLING 期恢复完整链路——**这是修复也是产品观：危机用户更需要被看见，而不是被关掉功能**。
- 新增 `@Scheduled` 每日 04:00 危机巡检任务（首个定时任务，`@EnableScheduling`）。
- `risk_event.reviewed` 位接入 A2 复核队列；HIGH 事件 24h 内未复核 → 通知中心提醒管理员。
- 否定/引文防护：`RiskRules` 增加**前窗否定检测**（命中点前 6 字内含"不/别/没/无/禁止/千万别/新闻说/朋友说"则降为 MEDIUM 并标记 `needsReview=true`）；修复词表重复项；规则表从 Java 硬编码迁到 `resources/risk/rules.json`（热加载）。

**验收**：模拟用户触发 HIGH → 7 天模拟推进 → 状态自动迁移全程可测；危机期间所有导出/档案接口仍可用（危机不剥夺数据所有权）。

> **实现注记（M5，2026-09-19）**：状态机落在 `CrisisLifecycleService`（`crisis_lifecycle` 表留痕每次迁移），CRISIS 7 天强干预 → COOLING → 连续 2 自然周 avgValence>-0.3 且无新 risk_event 自动结案，累计 2 次再入置 REVIEW 进人工队列；每日巡检由 `DailySweeper` 04:00 驱动（`@EnableScheduling` 已开）。`DiaryPipeline.steps()` 仅 `crisis_state==CRISIS` 时截断两步，COOLING 恢复完整链路（回归测试覆盖）。`RiskRules` 已外置 `resources/risk/rules.json` 并支持 reload，前窗否定检测命中降 MEDIUM+`needsReview`（`risk_event.needs_review` 新列）；**已知限制**：`NpcDirector` 危机词表是 static final 类加载固化，rules.json reload 不传播到 NPC 链路（M9 修）。`user` 实际新增列为 `crisis_state/crisis_started_at/crisis_ends_at`（`deletion_requested_at` 归 S2），`policy_version` 未动（协议重签留待后端有版本化条款时）。

#### S2 账号注销与数据导出自服务（合规闭环）

- `POST /users/me/delete`：二次确认（输入密码）→ 立即 `status=3` + JWT 拉黑 → 7 天冷静期（可登录撤回）→ 到期任务销毁全部用户 DEK（调用已有 `destroyUserKeys()`）→ 密文永久不可读，仅保留审计哈希链所需的最小记录。
- `GET /users/me/data-export`：个人数据可携带权——把自己全部明文数据（日记/报告/训练/打卡）打包 JSON 下载，走 S4 的异步任务 + 限时链接同款机制。
- 协议重签：`agreed_policy_at` 下发到 `/auth/me`，条款版本升级后前端 modal 强制重确认。

> **实现注记（M5）**：`AccountService` 落地全流程——`POST /users/me/delete`（密码二次确认→status=3→`jwt.revokeAll` 即时吊销全部会话）→ 冷静期内登录放行且 `TokenResp.deletionPending=true`（前端登录页/首页弹"撤回注销"横幅）→ `POST /users/me/delete/cancel` → `DailySweeper` 调 `processExpiredDeletions()` 销毁 DEK+匿名化昵称+清手机号+置 deleted_at。导出：`GET /users/me/data-export` 生成快照（diaries 明文/reports/emotionPoints/profiles/exerciseRecords/riskEvents；打卡待 M7 G1 接入）→ `POST /users/me/data-export/{fileId}` 一次性领取，链接 5min TTL 且用后作废。**偏差**：快照暂存内存 TTL store，下篇·七规划的 `export_record` 表 M5 未建（留痕靠审计事件，多节点/重启丢快照归技术债 Redis 化一并解决）；改密 `PUT /users/me/password` 视为凭证变更同样 revokeAll（S3 联动）。协议重签 modal 未做（无版本化条款可签）。

#### S3 认证加固

- Refresh token **轮换 + 重用检测**：每次 refresh 拉黑旧 jti；检测到已拉黑 refresh 被再次使用 → 吊销该用户全部令牌（疑似被盗）。
- 登录失败计数（Redis，5 次/15min 锁定），`LOGIN_FAILED` 写审计。
- CORS 配置真实 `CorsConfigurationSource` bean（白名单从环境变量读）。
- 全局异常映射改真实 HTTP 状态码（4xx 客户端错、5xx 服务端错），保留 body 内 code。

> **实现注记（M5）**：全部落地（`AuthHardeningTest` 4 例覆盖）。refresh 轮换在 `JwtService.parseForRotation`：验签/typ/epoch 后查黑名单，命中已拉黑 jti → `revokeAll` + 审计 `TOKEN_REUSE_REVOKE`；前端 `http.ts` 以 single-flight 防并发刷新。**epoch 吊销语义（两轮修正）**：`revokeAll` 存原始毫秒值；标准 `iat` 只有秒级精度，截断到秒会漏吊销同秒新签令牌，先改为 `iat.toEpochMilli() <= epoch` 即拒（同秒宁可错杀 <1s 窗口）——真机冒烟证明该窗口在"注销申请→立即冷静期登录"链路会真实命中，最终方案：签发时自填毫秒级 `iatms` 自定义 claim，parse 优先用 `iatms` 比对（无此 claim 的旧令牌退回 iat 秒级、维持宁错杀），吊销不可漏且不再错杀。登录锁定计数 key `jwt:login-fail:{username}`（5 次/15min，Redis INCR+EXPIRE），锁定期内正确密码也拒并提示"稍后再试"。HTTP 状态码映射：401 未认证 / 403 越权或已吊销 / 409 冲突 / 404 / 429 限流 / 503 LLM 不可用 / 400 参数 / 500 兜底。

#### S4 SSE 可靠流（多 Agent 可视化的信任基础）

- 事件补 `id:`（ULID），`TaskEventBus` 为每个 task 保留最近 64 条事件的环形缓冲（Redis Stream，顺带解决多节点）；重连带 `Last-Event-ID` → 从断点重放。
- 前端 `streamTask` 断线自动重连（指数退避 ≤3 次），失败降级为 `GET /tasks/{taskNo}` 轮询（该端点已存在但闲置）——**保证 UI 永不卡死在 loading**。
- 心跳 `: ping`（每 20s），防代理掐线；`AbortController` 全量接入，离开页面即断流。

> **实现注记（M5）**：事件 id 用**单调递增序号**（非 ULID，重放按 `id>lastEventId` 比较需要有序）；`TaskEventBus` 每任务 `Stream{emitters, ArrayDeque 环形缓冲 64 条, seq, terminal, lastActive}`，**无订阅者也缓存**（task_created 在 submit 时即入缓冲，稍后订阅自动补发），`subscribe(taskNo, lastEventId)` 重放后挂实时流、终态则重放完直接 complete；20s 守护线程心跳 comment，terminal 或空流闲置 10min 清理。**偏差**：缓冲为单节点内存版，规划的 Redis Stream（`orch:events:{taskNo}`）与 `task_instance.next_event_seq` 未做，归技术债清单第 2 条一并清偿（接口 `publish/subscribe` 已按可切换设计）。前端 `sse.ts`：解析 `id:` 行记录 lastId，断线重连 ≤3 次（800ms×n 退避、带 Last-Event-ID 头），仍失败降级 `GET /tasks/{taskNo}` 轮询（2s×60）并在终态合成 done 事件——UI 永不卡 loading；`postSse` 一次性流不重连。`TaskEventBusTest` 2 例 + 真机重放演示见 `deploy/tools/smoke_m5.mjs`。

### L2 核心体验补全（P0/P1）

#### C0 树洞漫聊（陪聊对话空间，V2 一级入口）

**动机**：写日记是"高门槛记录"，倾诉才是本能需求。参考豆包式自由对话：用户分享日常、发牢骚、说废话都行，AI 是"屿岛上话搭子"而非咨询师；对话记录经用户知情后沉淀为画像与风险数据源——**把产品的数据入口从"一天一篇"扩展到"随来随聊"**。

**产品形态**：
- 全屏幕连续对话页 `/companion`，无场景设定、无轮数上限（软上限 200 轮/日，成本护栏）；会话按"自然日+30min 静默"分段，随时续聊；
- 陪伴人设（v1 定稿）：温柔克制的岛民，会好奇、会记住、**不说教不诊断不替用户下结论**；回复短（1–3 句为主）、口语化、可发问延续话题，情绪重时先接住再陪伴；
- "豆包感"的核心是**记得你**：每轮 prompt 由 ContextAssembler 注入近 7 天画像摘要 + 事件标签（不注入原文）——"上次说的那个室友，后来你们说话了吗？"；
- 聊天内轻反馈：用户可长按自己的话点"这句别分析"（本段排除画像管道）；设置里可整体关闭"漫聊参与情绪分析"（关闭后仅作留存对话）。

**架构设计（复用大于新建）**：
- **第六个 Agent `CompanionAgent`（漫聊陪伴）**：注册进 AgentRegistry，实时对话走类 SimulationService 的会话引擎（复用 SSE 流式、乐观 UI、断线处理），但**无 NpcDirector 张力状态机**——导演模块替换为"情绪响应策略"：跟随用户效价，负面时降能量匹配、稳定后温和拉升（禁止强行正能量）；
- **每轮强制实时风险检测**：`RiskRules.scan(userText)` 在回合入口同步执行（与 NpcDirector 同路径，规则一票）——命中 HIGH → 当轮回复被替换为温和陪伴 + 转介卡流式插入 + 走 S1 危机生命周期；**倾诉场景是高危表述最高发入口，此项为 P0 中 P0**；
- **COMPANION_PIPELINE（异步消化，非每轮）**：会话分段结束/日终触发 `摘要提取 → EMOTION(source_type=CHAT) → RISK_ARCHIVE`；TRACE 仅在 CHAT 情绪显著负面时按分支加入生成轻量洞察（"想不想看看这段聊天透露了什么"卡片，可忽略）；
- 数据落 `companion_session/companion_turn`（用户消息 ✦ 加密，同 simulate 表规范），纳入 S2 注销销毁与档案导出。

**边界守护（三层约束延伸）**：
- 漫聊输出同样过 `DISCLAIMER_POLICY` + 诊断词拦截；
- 明示话术：首次进入展示"我是自助陪伴工具，不是心理咨询师"确认条（一次性，之后收进设置）；
- 防依赖机制：连续 3 日单日 >100 轮时，插入一次"这几天聊得很多，要不要把心事写成日记做个深度梳理，或者看看校心理中心"的引导（**陪伴导向行动，不导向依赖**）。

**验收**：① 高危句式在漫聊路径 100% 当轮拦截（并入 CI 回归集）；② 画像注入续聊演示（提到过的实体被正确回引）；③ "这句别分析"生效于下一次管道消化；④ Mock 下 COMPANION_PIPELINE 契约测试。

# 心枢 · 多Agent全链路青年心理自助成长平台｜定稿版

> 面向求职简历，整体架构、业务边界、Agent 协同、技术栈全部敲定，面试可以直接讲。
> 核心定位：面向大学生群体的**任务驱动型多智能体协同心理自助成长平台**。用于情绪觉察、压力溯源、人际沟通仿真训练、自助情绪调节、风险筛查归档；**仅为自助辅助工具，不做心理诊断、不替代心理咨询师**。
> 
> 

## 一、整体架构

**调度中心（核心控制服务）**
负责任务分发、状态管理、Agent 之间消息与中间结果流转、会话上下文管理、权限与隐私校验。
五个智能体是系统内的独立业务推理单元，**按需唤起，不是同时在线聊天**。

### 五大智能体

1. **情绪感知 Agent**
接收用户日记 / 心情文本，完成情感识别、情绪强度提取、事件标签分类，更新用户情感画像，输出情绪时序数据。

2. **溯源推理 Agent**
基于情绪感知 Agent 输出的中间结果，推理压力来源，识别认知思维误区，以苏格拉底提问引导用户自我反思，生成事件 \- 情绪 \- 想法复盘报告。

3. **心智训练 Agent**
人际场景仿真核心，可扮演多方角色，和用户实时对话博弈；场景结束后自动复盘沟通问题，给出表达优化建议。

> 预设场景：宿舍冲突、小组项目分歧、亲子沟通、亲密关系矛盾（4 个核心场景）
> 
> 

4. **疏导干预 Agent**
根据用户当前情绪、压力类型，匹配轻量化自助练习（正念、54321 感官练习、认知书写练习），生成短期减压方案、心理科普内容。

5. **风险研判 \& 归档 Agent**
持续评估风险等级（低 / 中 / 高）；高危触发转介提示；归档全部会话、报告、情绪记录；生成可导出的个人成长档案，负责数据加密存储。

## 二、业务主流程

1. 用户登录 Web 平台，撰写情绪日记或者选择人际模拟训练功能

2. 调度中心接收请求，分配任务给对应 Agent

3. Agent 产出中间结果，回传给调度中心，按需传给其他 Agent 继续处理

4. 任务完成，交由【风险研判 \& 归档 Agent】评估风险、持久化保存数据

5. 页面展示可视化结果：情绪曲线、复盘报告、训练总结、自助练习方案

## 三、技术栈（后端为主，贴合你的技术储备）

- 后端：SpringBoot \+ SpringSecurity（用户权限、隐私控制）

- 数据库：MySQL（用户、会话、报告）\+ Redis（会话上下文、任务状态缓存）

- 向量 / 知识图谱：Neo4j，存储心理学常识、认知误区库、沟通案例库

- LLM 服务：调用大模型 API，封装统一推理接口；多 Agent 调度服务自研

- 前端：Vue3，提供 Web 交互面板、情绪图表可视化、报告预览导出

- 额外：数据加密，用户心理敏感数据加密存储

## 四、简历描述（直接复制）

> **心枢 \- 多 Agent 全链路青年心理自助成长平台**
> 基于任务调度架构设计的多智能体协同心理自助系统，面向大学生群体。平台包含情绪感知、压力溯源、人际仿真训练、自助疏导、风险归档五大智能体。调度中心负责任务分发与多 Agent 之间的数据流转，实现情绪日记解析、情感画像构建、认知误区推理、多角色人际情景模拟、情绪调节方案生成、心理风险分级预警与成长档案管理。系统严格划定产品边界，仅作为心理自助工具，高危用户引导至线下心理援助渠道；实现敏感数据加密存储，保障用户隐私。
